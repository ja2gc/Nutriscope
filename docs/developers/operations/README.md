APK publication's fingerprint-pinning gap is recorded in [workflow consumers](../../operations/environment.md#which-workflow-reads-which-secret).
- [Production Compose](../../../docker-compose.prod.yml) declares HTTP, backups/default worker, scheduler and one-off release roles. [bootstrap/app.php](../../../backend/bootstrap/app.php) is the schedule authority for menu maintenance, follow-ups, report files/census, backups and audit retention.
- [Deploy workflow](../../../.github/workflows/deploy.yml) requires the complete backend PHPUnit suite against a disposable UTC MySQL service and the frontend type check before building images on the Actions runner or transferring them over fingerprint-verified SSH. [ops/deploy.sh](../../../ops/deploy.sh) owns image loading, revision/health checks, rollback tags and successful-deploy image retention. Run its isolated failure-path tests with `bash ops/tests/deploy.test.sh`; test isolation is documented in [testing](../platform/testing.md).
- [CI Compose override](../../../ops/compose-validation.yml) removes production env-file references only for offline configuration validation. Never include it in a production command; normal deployment still requires the production env file.
- [StoredObjectStorage](../../../backend/app/Services/StoredObjectStorage.php), [filesystems config](../../../backend/config/filesystems.php) and [upload limits](../../../backend/config/uploads.php) own durable file routing and limits.
- [ReportController](../../../backend/app/Http/Controllers/ReportController.php), [Reports](../../../backend/app/Services/Reports) and [report config](../../../backend/config/nutriscope-reports.php) own rendering, archives and cache. [ReportPreview](../../../frontend/components/ReportPreview.tsx) is the browser consumer.
- [Backup services](../../../backend/app/Services/Backup), [backup settings](../../../backend/config/nutriscope-backups.php) and [backup filesystem](../../../backend/config/filesystems.php) own recovery paths; see [backup/recovery](../../operations/backup-recovery.md).

For scheduled backups, [DispatchDueBackups](../../../backend/app/Services/Backup/DispatchDueBackups.php) calculates deadlines in the configured backup timezone (Asia/Manila by default) and stores `backup_schedule_periods.expires_at` as a UTC instant. [BackupRetentionService](../../../backend/app/Services/Backup/BackupRetentionService.php) uses these deadlines to retain active periods and set the archive's retention deadline. [BackupScheduleSettingsTest](../../../backend/tests/Feature/Backup/BackupScheduleSettingsTest.php) checks stored UTC values and the corresponding Manila deadlines.

The worker timeout is 1200 seconds; the production example uses REDIS_QUEUE_RETRY_AFTER=1260. Check the effective combination before changing it. CLI roles (worker, scheduler and release) explicitly use SIGTERM, overriding the shared Apache image's SIGWINCH; HTTP keeps Apache's graceful signal. The worker has a 21-minute stop grace period so an existing job can finish before Docker forces termination. Scheduler tasks include retention/deletion and recovery-test dispatch; starting a scheduler has side effects.

Keep MySQL, Redis and backend/frontend published ports private to loopback. Host Nginx terminates HTTPS. Primary private uploads have a named volume; report-cache and legacy public storage are not durable shared mounts in current Compose. Inventory all file locations before replacing containers or moving hosts.

Use user www-data for manually entered mutating Artisan commands in running containers. Release entrypoint already drops privileges for its CLI. A DB rollback does not reverse object operations; image rollback does not roll back schema/data.

Production Compose bounds each container's logs with Docker's `local` driver (three 10m files), routes Laravel logs through its existing stderr channel, and sets memory ceilings. [Apache prefork settings](../../../backend/apache-prefork.conf) cap the HTTP worker pool at four and recycle children after 500 connections. Internal Apache keep-alive is disabled so idle upstream connections cannot reserve that small pool; Nginx retains ownership of public HTTPS connections. The read-only [concurrency regression](../../../ops/tests/apache-concurrency.test.mjs) sends eight internal `/up` reads: run `docker exec -i nutriscope-frontend-1 node --input-type=module < ops/tests/apache-concurrency.test.mjs` from the server checkout. Its 1.5-second bound checks local request queueing, not public-network performance or load capacity. These are initial limits for isolation, not a load-tested capacity guarantee; see [VPS operations](../../operations/vps-setup.md#7-future-releases) for tuning and rollout checks. Existing hourly queue recycling stays in place.

After successful health/image verification, the deploy script removes dangling images older than 24 hours on the dedicated NutriScope host, including legacy builds without the newer app label. This runs automatically after successful deployments; failures skip cleanup. Current and `:rollback` image tags and images referenced by containers are retained, including on same-revision redeploys. It never prunes volumes or build cache and does not use `--all`. Broader Docker cleanup is not routine maintenance permission. Never remove volumes or ignored directories without checking ownership, purpose and backups. Local output/ and tmp/ are Git-ignored working directories; `.deploy/` holds the temporary image transfer archive.

## Changing reports and operational behavior

The shared report layout uses Calibri from `storage/app/private-uploads/report-fonts/` (`calibri.ttf`, `calibrib.ttf`, `calibrii.ttf`, `calibriz.ttf`). Provision these installation assets separately; they are not source dependencies or committed font binaries. The existing private-upload volume retains them across releases, and the PDF renderer writes its normal font cache under Laravel storage. When assets are absent, bundled DejaVu Sans remains the fallback. All report text inherits the same family; signature blocks share the table's outer content margins. Missing field values render blank rather than filler words or dashes. These presentation changes do not rewrite filed PDFs automatically. Source review: `0e1927e2` plus this report-layout change, 2026-11-06.

For PDF layout/text, start with [Blade report views](../../../backend/resources/views/reports) and [generators](../../../backend/app/Services/Reports/Generators). Follow [ReportService](../../../backend/app/Services/Reports/ReportService.php), [ReportTemplateController](../../../backend/app/Http/Controllers/ReportTemplateController.php) and [ReportBrandingController](../../../backend/app/Http/Controllers/ReportBrandingController.php) for template/branding inputs; inspect [ReportArchiveSettingController](../../../backend/app/Http/Controllers/Admin/ReportArchiveSettingController.php) for archive settings. Check which configuration is current versus snapshotted before changing historical output. Generate and inspect the affected PDF with synthetic data rather than relying only on HTML or tests.

For a schedule change, read bootstrap/app.php and the actual command/job, its queue, timeout, locks and side effects. For file changes, trace StoredObjectStorage and its caller through authorized download, cleanup and backup handling; changing a disk setting does not migrate existing bytes. See [backup/recovery](../../operations/backup-recovery.md) for evidence required before relying on a restore.
