# AI features

Verified against source: `275d66a106bc86605eb8d077dc081b079b454061` plus the recorded-intake comparison fix in this working tree (2026-10-28).

Purpose: maintain assisted PES wording and monitoring narration. AI does not own deterministic clinical calculations.

## Change the model or provider

1. Read [AIService](../../../backend/app/Services/AIService.php), especially draftPes and narrateMonitoring. Both call Anthropic Messages; diagnosis also requires structured JSON output, and requests include thinking settings. Choose an accessible model supporting these parameters; a model-name change is not proof of compatibility.
2. For this production Compose deployment, change ANTHROPIC_MODEL in [docker-compose.prod.yml](../../../docker-compose.prod.yml), under the shared backend environment. It overrides the dotenv setting for web, worker, scheduler and release. Rebuild/recreate through the approved deployment process. Native Laravel/non-Compose deployments read ANTHROPIC_MODEL via [services.php](../../../backend/config/services.php); rebuild Laravel config cache and restart long-running processes after changes.
3. Keep ANTHROPIC_API_KEY server-side. Create the receiving institution's provider account/project, arrange billing and create its own API key. [Official model IDs](https://platform.claude.com/docs/en/models/overview) and provider requirements change; check them before selection.
4. Update the input/output cost rates through the existing Admin AI usage settings when pricing changes. [AiUsageLimit](../../../backend/app/Models/AiUsageLimit.php) stores these rates; [AiUsageLog](../../../backend/app/Models/AiUsageLog.php) snapshots estimated cost for new usage records. Review fallback estimates in [aiTokenCost.ts](../../../frontend/lib/aiTokenCost.ts) and its consumers/tests too. Preserve historical estimates; they are not provider invoices.
5. Use synthetic regression fixtures for output/schema validation and failure behavior. Changing to a different provider requires a deliberate adapter/contract change; an OpenAI key cannot simply replace the Anthropic key.

## Change prompts, evidence or limits

[PesSuggestionService](../../../backend/app/Services/Diagnosis/PesSuggestionService.php) and neighboring Diagnosis services gate evidence, validate candidates and retain drafts. [MonitoringController](../../../backend/app/Http/Controllers/RND/MonitoringController.php) owns monitoring review flow. Preserve evidence attribution, response bounds and editable-review behavior.

Diagnosis reviews reuse `PesSuggestionState` metadata. One provider call returns at most five new prioritized supported drafts, including multiple problems from one domain. Returned standard candidates are complete; omitted candidates and Other remain `not_returned` for deliberate retry. An omitted candidate is not proof that no diagnosis exists. Ordinary Generate reuses unchanged results without a provider call or allowance charge. Relevant required/corroborating and previously cited evidence invalidates review; unrelated edits preserve pending drafts. Related draft/saved-diagnosis deletion removes retained drafts and reopens the current candidate without generating. Legacy/missing provenance maps through canonical problem components; unmatched custom problems reopen their domain's Other candidate. Duplicate protection checks saved diagnoses and pending drafts again during approval. Distinct Other labels may share an ID; web dismissal uses the individual draft UUID.

Review outcomes are `complete`, `no_supported`, `partial`, or `rejected`. Malformed, empty and partially accepted output stay cached. **Review again (uses 1 request)** sends explicit `retry_rejected` and preserves valid pending drafts; Generate never silently becomes a paid retry. Static rejection reasons are logged without patient findings. Candidate/evidence hashes are skip flags, not clinical conclusions. Generate remains clickable for exhausted evidence without a provider call or charge. The web distinguishes no additional applicable diagnosis from no supported output. Rejection does not establish that no applicable diagnosis exists. Loading, missing assessment, unavailable service/status and quota exhaustion remain disabled. Provider HTTP failures do not close review. Catalog v12 includes the context-library version and invalidates earlier pending reviews; saved diagnoses remain protected.

Version changes invalidate older pending drafts/reviews. Approved diagnoses remain saved. Within a version, unchanged valid drafts survive unrelated edits. Valid partial drafts hide the rejection warning/status hint while retaining the separate retry action. Empty rejected results show one explanation; quota and service errors remain visible.

The clinician-only NO domain contains **No nutrition diagnosis at this time**. It completes Diagnosis without E/S and must be the sole saved entry. Existing NO blocks manual addition, generation and approval on the server. The web disables Add/Generate and shows a persistent deletion instruction with no timeout. AI never creates NO, including after empty/withheld results. Recording NO clears pending review state; deletion permits fresh review. The forward migration extends the domain enum without rewriting saved diagnoses.

Usage counts come from each successful Messages response, not an account-wide billing-history query. Both AIService entry points require an authenticated user before contacting the provider and retain that user's ID for usage logging. AIService writes the usage record before output parsing and clinical validation, so withheld results still count. Paid diagnostics must use this normal logging path; intercepting a response and exiting before the write bypasses accounting. Cache/no-eligible-evidence skips make no provider request. HTTP failures or timeouts without returned usage have no token record; this does not prove the provider incurred no usage. Admin totals sum saved counts and USD estimates. USD is estimated from the rates active when the record is created; the peso display converts that estimate at the current dashboard exchange rate. Thus historical peso displays can change without rewriting saved USD. Historical USD rows missing an estimate were backfilled once by the October 20 migration using the rates then available; their original rates were not retained.

The Admin AI Usage Explorer defaults to Asia/Manila and offers UTC for provider comparisons. [AiUsageAnalyticsController](../../../backend/app/Http/Controllers/Admin/AiUsageAnalyticsController.php) applies the selected timezone to day/month buckets and period boundaries; the existing usage client passes `timezone=Asia/Manila` or `timezone=UTC`. This only regroups saved input/output counts and USD estimates; it does not rewrite records or change the Manila-based token caps and dashboard KPI periods. Provider comparisons also require matching API-key/workspace/model scope and reporting cutoff. The local ledger does not retain historical provider cache counters or guarantee account-wide completeness.

The native provider schema requires p for every draft: the supplied Problem label or a supported custom nutrition term for Other. Problem text allows 255 characters, E/S 75 each, and n/en/sn 100 each. Existing E/S choices pass lexical/numeric checks before being sent once per eligible domain. Brief prompt guidance covers the ten etiology categories and Assessment sources FH/AM/BD/PD/CH; codes/category annotations stay outside PES. Causes require concerning documented findings; medication/category names alone do not establish a cause. Core wording follows the [Academy's public PES guidance](https://www.eatrightpro.org/practice/nutrition-care-process/ncp-overview/nutrition-diagnosis). A raw meal excerpt does not prove an intake deficit/excess. Do not add provider-rejected regex length ranges. Entirely withheld generations log static reasons without clinical values.

Validation reuses candidate eligibility against cited concerning signs and required population context, including when a known Problem is returned through Other. Intake nutrient/direction must be supported by the Assessment and sign; explicit percentages or recorded intake-versus-needs amounts in the same units can establish direction without an invented cutoff. The comparison requires a stated needs/target reference, does not convert units and does not treat an ambiguous inequality as an exact intake. Normal and concerning clauses are evaluated separately. Structured sedentary activity can be cited. Causes use only cited cause fields; intake status alone is not a cause. Smoking/routine history requires a documented causal nutrition effect before use as etiology. Predictions use NI and require documented anticipated risk. Adult BMI rules do not establish pediatric diagnoses; a recorded pediatric classification can support its corresponding term. Malnutrition retains its separate criteria checks.

Lexical overlap is a wording check, not clinical verification. If a paraphrase cannot be verified, the server can retain the draft using concise cited concerning Assessment wording. Unsupported numbers remain rejected, including percentage claims borrowed from unrelated measurements. Sources too long for the E/S limit still need concise wording. These checks do not independently establish causality; RND review remains mandatory.

Behavioral review hashes include the candidate's required/corroborating findings and cited fields. Uncited referral/medication context does not independently reopen these reviews; cited clinical context still does. Intake/clinical candidates retain conservative clinical-context invalidation. Stored `review_contexts` and `review_outcome` are authoritative; no separate reviewed-ID or empty-result flag is written. Accepted drafts retain provider priority order.

[AiReviewAllowance](../../../backend/app/Support/AiReviewAllowance.php) uses Laravel's cache rate limiter and an atomic reservation lock: **10 generation attempts per 600-second window per authenticated RND, independently for diagnosis and monitoring**. Attempts include rejected/upstream-failed generations. Status, reuse, dismissal and approval consume no generation allowance. The old patient/day and monitoring-entry counters are no longer consumed; historical rows are preserved. Generation routes do not also apply the generic hourly AI throttle. Meal generation/approval retain their existing middleware. Global daily/monthly token caps and provider usage logging remain separate. UI counters refresh after expiry; opening another patient or draft does not reset the feature allowance.

Duplicate checks combine saved problem text, manual problem selections and the originating candidate identity of approved AI diagnoses. Common intake spelling variants are normalized while preserving intake direction and distinct nutrients. Generic **Other** categories remain label-based so one saved custom problem does not suppress every custom problem. Saved problems and approved draft references are checked again when resolving pending drafts for approval.

Food recall notes reuse Assessment's `dietary_intake` field. [FoodRecallService](../../../backend/app/Services/FoodRecallService.php) supplies a de-identified portion-scaled average per recorded day, recorded weekday/weekend counts and explicit nutrient units; manually recorded `intake_nutrients` remain separate estimates. Unknown amounts or units are omitted, not converted to zero. Both summaries participate in review invalidation. Numeric intake summaries are corroborating context and cannot independently establish a concerning cause or sign. Normal findings remain counterevidence. The Evidence used presentation is retained; AI draft **Extra Notes** uses the manual form's label.

## Selective clinical context

[ClinicalAiContext](../../../backend/app/Support/ClinicalAiContext.php) selects terse guidance from [clinical-ai-context.json](../../../backend/resources/clinical-ai-context.json). Condition cards match documented clinical context and evidence indicators; monitoring may also match intervention goal/type. Diagnosis additionally selects direction-specific nutrient guidance and documented routine cards for tobacco, alcohol, sleep/shift work, meal patterns, caffeine, restriction, activity, supplements and adherence. Denied findings do not establish a match. Possible effects are guidance, never patient findings or established causes. Selection happens on the server without a second AI call, embeddings, vector database or runtime guideline search.

The bounded library covers glycemia/A1c confounders, renal potassium/protein/anemia, cardiac lipids/fluid, postoperative intake, wounds, cirrhosis, albumin interpretation and adult malnutrition. Source editions span 2021–2026, including Academy's 2023 NCP tutorial, ADA 2026, KDIGO 2024/2026, AHA 2026 and ESPEN 2025. Source links/edition dates stay internal; selectors and source metadata are not sent to the provider. Cards distinguish possible contributors from documented causes and never supply an unrecorded prescription, deficiency or medical diagnosis. Recheck original sources before editing; source age alone is not proof of supersession. The application offers its existing PES terms, not a newly licensed complete NCPT catalog. No fixed diagnosis-count recommendation is claimed.

Both paths receive allowlisted referral medical diagnosis, Assessment nutrition care category/Other and medication text. The category is a care grouping, not physician diagnosis. Category/medication names alone cannot ground etiology; a medication effect or interaction needs documented findings. Known patient names (including name components), identifiers and contact details are redacted recursively from clinical text. No names or identifiers are deliberately included in provider payloads. Redaction is based on recorded identifiers, not a guarantee of recognizing arbitrary third-party names typed into narrative fields.

Diagnosis sends the existing bounded, allowlisted, deidentified Assessment snapshot, including normal findings/counterevidence, height/current/usual weight, relevant histories, labs, recall summaries and the cycle nutrition-support route. It excludes derived RND Summary, saved candidate IDs, identity and screening risk scores. This changes AI input only, with no Assessment-screen additions. The serialized input limit remains 16,000 bytes; trailing guidance cards are removed first when needed. Output allows 1,700 tokens for up to five new drafts. Reuse avoids repeated provider charges; provider prompt caching is not enabled. Deliberate new generation sends the snapshot again and consumes an attempt.

WHO monthly BMI bands apply at 61–228 completed months, Asia-Pacific afterward; under-five BMI is omitted. The diagnosis age_group treats the WHO range as pediatric so adult BMI/GLIM rules cannot establish pediatric diagnoses. Classes imply neither malnutrition, severity, etiology nor a target. Adult overweight eligibility/sign validation start at BMI 23; Underweight requires the supported adult finding. See [classification fields and scope](data.md). Monitoring includes its current class and age_group; pediatric measurements have no fixed adult BMI/IBW guide or achievement status. The adult two-decimal BMI range is 18.5–22.99; fallback goals are not inferred from a label.

The PES schema constrains candidate/evidence references to request-local enums and describes phrase lengths without provider-rejected regex ranges. Server checks retain the 255-character Problem and 75-character E/S limits. An isolated protein concern does not establish an energy concern. Quantities without an explicit intake comparison do not independently establish direction. Custom behavioral/clinical labels need corresponding nutrition findings, rather than a copied referral diagnosis; malnutrition retains its specific clinical-criteria checks. `n`, `en`, `sn` request an assessment fact plus why it supports P/E/S, mapped into `extra_notes`, `builder_data.etiology_notes`, `builder_data.sign_notes`; notes stay outside PES. Generated notes allow 100 characters. Missing, overlong, unsupported, repeated or component-only explanations are omitted without discarding an otherwise valid PES or adding another provider call. No repetitive fallback summary is manufactured. New numerical claims remain withheld. Manual notes retain 125 characters. Prompt limits, allowed IDs and conservative abstention reduce avoidable rejections; they cannot guarantee every response passes validation.

Monitoring remains plain text and rejects empty, truncated or over-700-character responses. Its 400-output-token prompt requests one paragraph, normally 250–450 characters, without treatment advice, new diagnoses, citations or framework names. Identical de-identified comparison inputs reuse a cached narrative for up to one day, scoped to RND/cycle/model/context/prompt version. **Regenerate AI Summary** explicitly bypasses reuse and consumes an attempt. Changed inputs select another cache key. Visit-history keys still reject stale requests/results; editing excludes the edited visit from its own baseline. Existing manual text is replaced only through **Use this summary**.

Monitoring comparison payloads include `recall_targets` only for recalled nutrients with an existing prescription target/range. `MonitoringPlanService` reuses its plan indicators and units; no target is invented. Recall estimates remain separate from entered indicator readings even when both describe the same nutrient. Context selection preserves a confirmed condition followed by a different negated finding, excludes suspected/ruled-out conditions, and uses potassium guidance applicable to either direction. Numeric clinical ranges retain their units during contact redaction.

[Admin limits](../../../backend/app/Http/Controllers/Admin/AiUsageLimitController.php) and [usage client](../../../frontend/services/aiUsageLimitService.ts) expose limits; AIService checks recorded usage before requests. These thresholds do not reserve spending for concurrent calls.
