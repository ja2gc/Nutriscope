# AI features

Verified against source: `5ac49380` plus grounded preset filtering and partial-result presentation in this working tree (2026-10-27).

Purpose: maintain assisted PES wording and monitoring narration. AI does not own deterministic clinical calculations.

## Change the model or provider

1. Read [AIService](../../../backend/app/Services/AIService.php), especially draftPes and narrateMonitoring. Both call Anthropic Messages; diagnosis also requires structured JSON output, and requests include thinking settings. Choose an accessible model supporting these parameters; a model-name change is not proof of compatibility.
2. For this production Compose deployment, change ANTHROPIC_MODEL in [docker-compose.prod.yml](../../../docker-compose.prod.yml), under the shared backend environment. It overrides the dotenv setting for web, worker, scheduler and release. Rebuild/recreate through the approved deployment process. Native Laravel/non-Compose deployments read ANTHROPIC_MODEL via [services.php](../../../backend/config/services.php); rebuild Laravel config cache and restart long-running processes after changes.
3. Keep ANTHROPIC_API_KEY server-side. Create the receiving institution's provider account/project, arrange billing and create its own API key. [Official model IDs](https://platform.claude.com/docs/en/models/overview) and provider requirements change; check them before selection.
4. Update the input/output cost rates through the existing Admin AI usage settings when pricing changes. [AiUsageLimit](../../../backend/app/Models/AiUsageLimit.php) stores these rates; [AiUsageLog](../../../backend/app/Models/AiUsageLog.php) snapshots estimated cost for new usage records. Review fallback estimates in [aiTokenCost.ts](../../../frontend/lib/aiTokenCost.ts) and its consumers/tests too. Preserve historical estimates; they are not provider invoices.
5. Use synthetic regression fixtures for output/schema validation and failure behavior. Changing to a different provider requires a deliberate adapter/contract change; an OpenAI key cannot simply replace the Anthropic key.

## Change prompts, evidence or limits

[PesSuggestionService](../../../backend/app/Services/Diagnosis/PesSuggestionService.php) and neighboring Diagnosis services gate evidence, validate candidates and retain drafts. [MonitoringController](../../../backend/app/Http/Controllers/RND/MonitoringController.php) owns monitoring review flow. Preserve evidence attribution, response bounds and editable-review behavior.

Diagnosis reviews reuse `PesSuggestionState` metadata. One pass evaluates eligible candidates and returns at most three prioritized supported drafts, including multiple problems from one domain. Complete and valid empty results close their candidates; partial rejection permits explicit retry without automatic refill. Relevant required/corroborating evidence and previously cited findings participate in invalidation. Unrelated edits preserve pending drafts. Deleting a related draft or saved diagnosis removes its retained draft and reopens its current candidate. Legacy/missing provenance maps through canonical problem components; unmatched custom problems reopen only their domain's Other candidate. Deletion does not generate automatically. Duplicate protection still checks saved diagnoses and remaining drafts. Distinct Other labels may share an ID; web dismissal uses the individual draft UUID.

Review outcomes are `complete`, `no_supported`, `partial`, or `rejected`. Malformed, entirely rejected and partially accepted output stay cached; **Retry AI Review** requires explicit `retry_rejected` and preserves valid pending drafts. Static rejection reasons are logged without patient findings. A completed candidate/evidence context hash is the skip flag, rather than a field-level medical conclusion. Generate remains clickable for exhausted evidence: POST returns **No supported evidence left.** as a warning, without another provider call or allowance charge. Loading, missing assessment, unavailable status/service and quota exhaustion remain disabled. Provider HTTP failures do not close review. The catalog/review version includes the context-library version; bump the catalog when review behavior changes. Version 7 reopens reviews completed under the previous deletion/partial-rejection behavior; saved diagnoses remain protected.

Version changes invalidate older review states and pending drafts, requiring fresh generation under the current checks. Approved diagnoses remain saved. Within a version, unchanged valid pending drafts survive unrelated edits. When valid pending drafts remain after a partial rejection, the web hides the rejection warning/status hint but preserves deliberate Retry. Empty rejected results still show the explanation; quota and service errors remain visible.

The native provider schema requires p for every draft: the supplied problem label, or a supported custom nutrition term for Other. Field descriptions and the prompt specify p/e/s at 1–75 characters and n/en/sn at 0–100. Existing E/S builder choices pass the same lexical/numeric grounding checks before being sent once per eligible domain. Causes use only the existing concerning cause fields, with referral diagnosis separated from medication/category context. This removes presets already known to fail those checks; it is not independent clinical verification of every offered option. Supported choices should be returned verbatim, with specific Other text only when none fits. Core wording must describe a nutrition problem, its documented cause and specific proof, following the [Academy's public PES guidance](https://www.eatrightpro.org/practice/nutrition-care-process/ncp-overview/nutrition-diagnosis). A raw meal excerpt does not by itself prove inadequate/excessive intake. Do not add regex length ranges: the deployed provider rejected them with HTTP 400, despite [documented support for some simple ranges](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#json-schema-limitations). Entirely withheld generations log the existing static rejection reason at error level without clinical values. Catalog v10 invalidates the earlier drafts/reviews.

Validation reuses candidate eligibility against the cited concerning signs plus required population context, so an unrelated concern cannot establish a different problem. Intake direction must occur in both the assessment narrative and returned sign. Causal wording is grounded only in the cited fields accepted as causes; energy-intake status is not a cause. The legacy Clinical predicted-intake card is no longer offered by AI because the current Intake builder supports only Inadequate/Excessive nutrient intake terms; manual options and saved history are preserved. Lexical grounding normalizes some synonyms and stopwords, then requires at least two-thirds unique-word overlap with the cited source. It can reject valid paraphrases and admit clinically weak matches; it is not independent clinical causality verification. Candidate gates reduce known failures, but RND review remains mandatory.

Behavioral review hashes include the candidate's required/corroborating findings and cited fields. Uncited referral/medication context does not independently reopen these reviews; cited clinical context still does. Intake/clinical candidates retain conservative clinical-context invalidation. Stored `review_contexts` and `review_outcome` are authoritative; no separate reviewed-ID or empty-result flag is written. Accepted drafts retain provider priority order.

[AiReviewAllowance](../../../backend/app/Support/AiReviewAllowance.php) uses Laravel's cache rate limiter and an atomic reservation lock: **10 generation attempts per 600-second window per authenticated RND, independently for diagnosis and monitoring**. Attempts include rejected/upstream-failed generations. Status, reuse, dismissal and approval consume no generation allowance. The old patient/day and monitoring-entry counters are no longer consumed; historical rows are preserved. Generation routes do not also apply the generic hourly AI throttle. Meal generation/approval retain their existing middleware. Global daily/monthly token caps and provider usage logging remain separate. UI counters refresh after expiry; opening another patient or draft does not reset the feature allowance.

Duplicate checks combine saved problem text, manual problem selections and the originating candidate identity of approved AI diagnoses. Common intake spelling variants are normalized while preserving intake direction and distinct nutrients. Generic **Other** categories remain label-based so one saved custom problem does not suppress every custom problem. Saved problems and approved draft references are checked again when resolving pending drafts for approval.

Food recall notes reuse Assessment's `dietary_intake` field. [FoodRecallService](../../../backend/app/Services/FoodRecallService.php) supplies a de-identified portion-scaled average per recorded day, recorded weekday/weekend counts and explicit nutrient units; manually recorded `intake_nutrients` remain separate estimates. Unknown amounts or units are omitted, not converted to zero. Both summaries participate in review invalidation. Numeric intake summaries are corroborating context and cannot independently establish a concerning cause or sign. Normal findings remain counterevidence. The Evidence used presentation is retained; AI draft **Extra Notes** uses the manual form's label.

## Selective clinical context

[ClinicalAiContext](../../../backend/app/Support/ClinicalAiContext.php) selects terse interpretation guidance from [clinical-ai-context.json](../../../backend/resources/clinical-ai-context.json). Diagnosis requires matching documented clinical context plus supplied evidence indicators; monitoring may also match the selected intervention goal/type. A selected goal does not establish a medical diagnosis. No matching card sends no extra guidance. Common behavioral findings need no specialist card. This is rule-selected context augmentation; no embeddings, vector database, runtime guideline search or model training.

The bounded library covers glycemia/A1c confounders, renal potassium/protein/anemia, cardiac lipids/fluid, postoperative intake, wounds, cirrhosis, albumin interpretation and adult malnutrition. Source editions span 2021–2026, including Academy's 2023 NCP tutorial, ADA 2026, KDIGO 2024/2026, AHA 2026 and ESPEN 2025. Source links/edition dates stay internal; selectors and source metadata are not sent to the provider. Cards distinguish possible contributors from documented causes and never supply an unrecorded prescription, deficiency or medical diagnosis. Recheck original sources before editing; source age alone is not proof of supersession. The application offers its existing PES terms, not a newly licensed complete NCPT catalog. No fixed diagnosis-count recommendation is claimed.

Both paths receive allowlisted referral medical diagnosis, Assessment nutrition care category/Other and medication text. The category is a care grouping, not physician diagnosis. Category/medication names alone cannot ground etiology; a medication effect or interaction needs documented findings. Known patient names (including name components), identifiers and contact details are redacted recursively from clinical text. No names or identifiers are deliberately included in provider payloads. Redaction is based on recorded identifiers, not a guarantee of recognizing arbitrary third-party names typed into narrative fields.

Anthropometric diagnosis input includes supported calculated BMI/class and relevant weight-change direction/percentage/duration. WHO monthly bands apply at 61–228 completed months, Asia-Pacific afterward; under-five BMI is omitted. The diagnosis evidence age_group treats the WHO range as pediatric so adult BMI/GLIM rules cannot establish pediatric diagnoses. Height stays local; current/usual weights are sent for weight-loss candidates. Additional anthropometrics remain candidate-specific. Numeric risk scores and legacy screening-derived nutritional_status are excluded. Classes imply neither malnutrition, severity, etiology nor a target. Adult overweight eligibility/sign validation start at BMI 23; Underweight requires the supported adult finding. See [classification fields and scope](data.md). Monitoring includes its current class and age_group; pediatric measurements have no fixed adult BMI/IBW guide or achievement status. The adult two-decimal BMI range is 18.5–22.99; fallback goals are not inferred from a label.

The PES schema constrains candidate/evidence references to request-local enums and describes phrase lengths without provider-rejected regex ranges. Server checks retain the 75-character core-field limit. An isolated protein concern does not establish an energy concern. Quantities without an explicit intake comparison do not independently establish direction. Custom behavioral/clinical labels need corresponding nutrition findings, rather than a copied referral diagnosis; malnutrition retains its specific clinical-criteria checks. `n`, `en`, `sn` request an assessment fact plus why it supports P/E/S, mapped into `extra_notes`, `builder_data.etiology_notes`, `builder_data.sign_notes`; notes stay outside PES. Generated notes allow 100 characters. Missing, overlong, unsupported, repeated or component-only explanations are omitted without discarding an otherwise valid PES or adding another provider call. No repetitive fallback summary is manufactured. New numerical claims remain withheld. Manual notes retain 125 characters. Prompt limits, allowed IDs and conservative abstention reduce avoidable rejections; they cannot guarantee every response passes validation.

Monitoring remains plain text and rejects empty, truncated or over-700-character responses. Its 400-output-token prompt requests one paragraph, normally 250–450 characters, without treatment advice, new diagnoses, citations or framework names. Identical de-identified comparison inputs reuse a cached narrative for up to one day, scoped to RND/cycle/model/context/prompt version. **Regenerate AI Summary** explicitly bypasses reuse and consumes an attempt. Changed inputs select another cache key. Visit-history keys still reject stale requests/results; editing excludes the edited visit from its own baseline. Existing manual text is replaced only through **Use this summary**.

Monitoring comparison payloads include `recall_targets` only for recalled nutrients with an existing prescription target/range. `MonitoringPlanService` reuses its plan indicators and units; no target is invented. Recall estimates remain separate from entered indicator readings even when both describe the same nutrient. Context selection preserves a confirmed condition followed by a different negated finding, excludes suspected/ruled-out conditions, and uses potassium guidance applicable to either direction. Numeric clinical ranges retain their units during contact redaction.

[Admin limits](../../../backend/app/Http/Controllers/Admin/AiUsageLimitController.php) and [usage client](../../../frontend/services/aiUsageLimitService.ts) expose limits; AIService checks recorded usage before requests. These thresholds do not reserve spending for concurrent calls.
