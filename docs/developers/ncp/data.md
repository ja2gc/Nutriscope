# NCP data meaning

Verified against source: `79ee23b53a0ba047faa791cdb8e5b7fcb1211429` plus clinical AI changes and review corrections in this working tree (2026-10-25).

Purpose: explain important clinical data families and route maintainers to their authoritative writers/consumers. No patient data or independently certified clinical guidance is included.

| Fields / family | Meaning and authority |
|---|---|
| NcpRecord.patient_id, rnd_user_id, type, status | Cycle context and ownership; [NcpRecord](../../../backend/app/Models/NcpRecord.php), [NcpRecordController](../../../backend/app/Http/Controllers/RND/NcpRecordController.php), [NcpAppointmentWorkflow](../../../backend/app/Services/NcpAppointmentWorkflow.php). Check transitions/permissions, not only a status label |
| risk_score, risk_score_manual_override, risk_score_manual_factors | Calculated score and explicit override metadata; [RiskScoreCalculator](../../../backend/app/Services/RiskScoreCalculator.php), cycle model and assessment/save routes. Score has a decimal:2 model cast; do not turn it into an AI-generated diagnosis |
| Assessment.nutritional_status | Screening-derived classification written by [AssessmentController::saveRiskScore](../../../backend/app/Http/Controllers/RND/AssessmentController.php) using [RiskScoreCalculator](../../../backend/app/Services/RiskScoreCalculator.php), including manual risk-factor overrides. Values include Normal, Moderate Malnutrition and Severe Malnutrition; these labels alone do not establish a clinical malnutrition diagnosis. The intervention calculator does not automatically consume this field as its clinical nutrition status. Confirmed liver calculation status is supplied separately through calculation_options.nutrition_status. Verified against `79ee23b53a0ba047faa791cdb8e5b7fcb1211429` on 2026-10-25; see [intervention source and default boundaries](../../logic/intervention-goals.md#5-adult-goal-calculations-sources-versus-proposed-defaults) |
| bmi_classification, bmi_reference_date | Derived read-only API fields, not stored columns. Assessment::classifyBmi uses the cycle date and completed age months: official WHO 2007 sex-specific bands at 61–228 months, Asia-Pacific afterward; month 60 has BMI without classification. WHO cutoffs are strictly below −3/−2 SD for severe thinness/thinness and above +1/+2 SD for overweight/obesity. Offline expanded-table thresholds retain published 0.001 precision in backend/resources/who-bmi-for-age.json and the matching frontend/lib copy; source URLs, retrieval date and workbook hashes are embedded. No interpolation, exact z-score or runtime fetch. Unknown required age/sex, invalid BMI, edema or maternal status withhold class. Ages 0–4 omit BMI in assessment/monitoring writes, API, AI and new reports; older stored values are preserved. Adult IBW/BMR/TEE panel estimates and monitoring IBW targets are withheld through month 228; the prescription engine retains its existing methods. AssessmentResource exposes the reference date and strips neither raw height nor weight; the web strips derived fields from saves. NcpSummaryGenerator prints classification separately from risk; census adult bands leave pediatric rows Unspecified. Monitoring AI uses observed_at. PES anthropometric eligibility treats the WHO age range as pediatric, preventing adult BMI/GLIM rules from establishing a pediatric diagnosis |
| Assessment.weight, height, dry_weight_kg, edema_present | Measurement/context inputs; [Assessment](../../../backend/app/Models/Assessment.php), [InterventionCalculationContextService](../../../backend/app/Services/InterventionCalculationContextService.php) maps weightKg/heightCm and chooses the measured/dry weight basis. Trace field_sources/measurement date rather than assuming the assessment is always the newest source |
| muac_mm, waist_cm, hip_cm | Different explicit units in Assessment. Preserve request limits and conversions; do not apply one shared unit by appearance |
| MUAC screening display | [getMuacScreening](../../../frontend/lib/anthropometricSafety.ts) uses known age at the classification reference date and mm: only 6–59 months receive Very low MUAC (<115), Low MUAC (115–<125), or Above screening cutoff (>=125). These are screening observations, not automatic MAM/SAM or adult malnutrition diagnoses. Measurements remain visible for other/unknown ages without a derived label. Above-cutoff values are omitted from the generated RND summary. Pediatric WHO growth z-scores are not automatically calculated |
| food_recall, intake_nutrients, allergies, food_dislikes | Structured clinical inputs in Assessment; [FoodRecallService](../../../backend/app/Services/FoodRecallService.php), [RecommendService](../../../backend/app/Services/RecommendService.php) and [MealPlanService](../../../backend/app/Services/MealPlanService.php) consume relevant food/intake context. Read the selected calculation path before changing the JSON shape |
| Assessment.dietary_intake | Optional Food recall notes, edited beside the recall calculator using the existing 250-character field and Assessment request/save path. [PesEvidenceBuilder](../../../backend/app/Services/Diagnosis/PesEvidenceBuilder.php) includes this narrative as assessment evidence; editing it can reopen relevant diagnosis reviews |
| Diagnosis review intake evidence | `FoodRecallService::evidenceSummary` derives sample-day averages from frozen nutrient snapshots and compatible saved portions; `intakeEvidence` supplies explicit units for separately entered amounts. Macro values retain kcal/g units and supported micronutrients use the existing monitoring unit definitions. No density assumption, unknown-to-zero substitution or addition of entered and calculated estimates. Food identifiers/names are excluded from provider summaries; see [AI maintenance](ai.md) |
| PesSuggestionState.provider_metadata | [PesSuggestionService](../../../backend/app/Services/Diagnosis/PesSuggestionService.php) writes per-candidate hashes, relevant keys and explicit review outcomes. Status/generation/resolution reuse them. Every candidate in a completed pass closes, including partial output. Rejected output permits deliberate retry, never an automatic refill. Relevant required/corroborating/cited evidence changes reopen review; related deletion removes retained drafts and matching review contexts. See [AI maintenance](ai.md) |
| Referral/medication AI context | Patient.medical_diagnosis is referral information; Assessment.primary_diagnosis_category/other groups nutrition care and is not medical diagnosis. Assessment.medications contains clinician-entered text. [ClinicalAiContext](../../../backend/app/Support/ClinicalAiContext.php) allowlists and redacts these fields for diagnosis evidence and monitoring comparisons; provider guidance never becomes patient evidence |
| Diagnosis justification notes | [PesSuggestionService](../../../backend/app/Services/Diagnosis/PesSuggestionService.php) maps provider n/en/sn into extra_notes and builder_data.etiology_notes/sign_notes using [DiagnosisBuilder](../../../backend/app/Support/DiagnosisBuilder.php). Accept/edit/save preserve notes separately from core PES. Generated notes allow 100 characters; manual notes 125. Invalid optional wording uses a grounded summary; core P/E/S validation remains mandatory |
| Intervention.energy_kcal, protein_g, carbs_g, fat_g, fluid_ml | Saved prescription quantities with decimal:2 casts; [Intervention](../../../backend/app/Models/Intervention.php), [NutritionPrescriptionService](../../../backend/app/Services/NutritionPrescriptionService.php), [InterventionPlanService](../../../backend/app/Services/InterventionPlanService.php). Generated reports round macros to whole numbers; other clinical numeric report displays trim unnecessary zeros. Stored precision and other website nutrient displays remain unchanged |
| goal_type, disease_stage, calculation_options, calculation_snapshot | Goal and calculation context/history; follow the plan service and [calculation context](../../../backend/app/Services/InterventionCalculationContextService.php). The snapshot is not a fresh recomputation against today's measurements |
| source_monitoring_id and latestIntervention | Links follow-up input to intervention history; NcpRecord selects latest intervention by created_at/id, while Intervention's update hook protects historical plans. Preserve those meanings across API/report changes |
| Monitoring indicators/comparisons | [MonitoringPlanService](../../../backend/app/Services/MonitoringPlanService.php), [MonitoringSummaryService](../../../backend/app/Services/MonitoringSummaryService.php), [Monitoring](../../../backend/app/Models/Monitoring.php). Baselines, targets and comparisons are different values; AI narrates bounded evidence. Only the newest saved entry by internal ID is editable/deletable in draft/active cycles, enforced in MonitoringController and exposed as can_edit/can_delete. Recall edits preserve saved nutrient baselines. clinical_summary is required with a 700-character limit. Reports print the saved evaluation and numeric intake; intake notes and symptoms feed AI instead of separate report columns |
| Monitoring AI recall_targets | Transient provider context written by `MonitoringPlanService::draftComparison`, consumed by `AIService::narrateMonitoring`. Maps only populated recall nutrient keys to existing prescription unit, target and reference bounds from plan indicators. Uses kcal/g/mg/other indicator units without conversion; unknown guides are omitted. Does not merge recall estimates into entered `indicators.current` readings or persist a new prescription. See [AI maintenance](ai.md) |
| Census classification basis and history | [DemographicCensusGenerator](../../../backend/app/Services/Reports/Generators/DemographicCensusGenerator.php) basis 7 counts current adult BMI classes, with unsupported contexts Unspecified. The cycle-count/age-bucket rules are unchanged. [StoreMonthlyDemographicCensuses](../../../backend/app/Services/Reports/StoreMonthlyDemographicCensuses.php) creates missing completed periods and leaves existing census JSON, source counts, basis versions and frozen_at intact. [ReportController](../../../backend/app/Http/Controllers/ReportController.php) reads stored periods across versions and labels a selected view historical_or_mixed when it includes pre-7 classifications; otherwise asia_pacific_bmi. Web/PDF headings distinguish recorded historical status from current adult BMI classes. Old labels are not retroactively treated as confirmed diagnoses |
| FoodItem.serving_size, serving_unit, micronutrients, water_g | Clinical food quantities and structured nutrient data; [FoodItem](../../../backend/app/Models/FoodItem.php), [UsdaService](../../../backend/app/Services/UsdaService.php). USDA nutrient keys/mapping must stay compatible with recipes and clinical rules |

Use [NCP maintenance](README.md) for HTTP owners, tests and domain explanations, and [general data tracing](../platform/data-semantics.md) before editing. Clinical recipes/FoodItem and operational FoodServiceRecipe/FsItem are distinct models; do not merge their units or calculations by field-name similarity.

Before changing clinical data, establish the relevant record shapes, migration history and clinical requirements. This selected map does not enumerate every clinical field; locate additional fields through models/requests and document only the behavior inspected.
